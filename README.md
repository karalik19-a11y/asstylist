# asStylist

**AI fashion director в Telegram Mini App.** По фотографии, росту, весу, выбранному стилю,
настроению и бюджету до **100 000 ₽** собирает персональный fashion look из проверенных товаров —
и объясняет, почему выбрана каждая вещь.

Сервис некоммерческий. Стоимость для пользователя — **0 ₽**: стек полностью бесплатный,
анализ фото по умолчанию работает локально, без API-ключей и внешних вызовов.

---

## Быстрый старт (2 команды)

```bash
make setup     # python venv + npm install
make run       # сборка Mini App + API на http://localhost:8000
```

Откройте `http://localhost:8000` — приложение работает и в обычном браузере (демо-режим),
и внутри Telegram как Mini App.

Без Makefile:

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
npm --prefix frontend install
npm --prefix frontend run build
.venv/bin/python -m uvicorn app.main:app --app-dir backend --host 0.0.0.0 --port 8000
```

Docker:

```bash
docker compose up --build     # http://localhost:8000
```

## Что работает сейчас

Вертикальный срез из ТЗ реализован полностью и проверен сквозными тестами:

```
Telegram Mini App → Home → Upload photo → Height → Weight → Style → Mood → Budget
→ Generate Look → Result Screen
```

Плюс то, что наращено поверх:

| Возможность | Где |
| --- | --- |
| Fashion Ranking Engine (8 факторов, детерминированный, объяснимый) | `backend/app/engine/ranking.py` |
| Бюджетный оптимизатор (ремонт вниз → апгрейды вверх, никогда не превышает бюджет) | `backend/app/engine/budget.py` |
| Анализ силуэта по росту/весу + фото, с честной величиной уверенности | `backend/app/engine/body.py` |
| Цветовой тип и палитра по фото (локально, Pillow) | `backend/app/vision/analyzer.py` |
| Product verification layer (9 проверок, контрольная сумма, белый список хостов) | `backend/app/verification/verifier.py` |
| Замена вещи в образе, избранное, история образов | `backend/app/services/look_service.py` |
| Демо/локальный режим: без токена бота, без сети, без ключей | `backend/app/config.py` |
| Каталог из 107 товаров (103 проходят верификацию, 4 намеренно битых) | `backend/app/catalog/products.py` |

## Архитектура

```
Telegram Mini App (React + TS + Vite)
        │  fetch /api/*  (один origin, без CORS-боли)
        ▼
FastAPI  ──►  Fashion Ranking Engine  ──►  Budget Optimiser  ──►  Look
   │                    ▲
   │                    │ только eligible-товары
   ├──► Verification Layer (schema / price / url / source / checksum / TTL)
   ├──► Vision (локальный Pillow-анализ, опционально OpenAI/Gemini)
   └──► SQLite (SQLAlchemy) — пользователи, образы, каталог
```

**Стек и почему он такой:**

| Слой | Технология | Причина |
| --- | --- | --- |
| Frontend | React 18 + TypeScript + Vite | самый стабильный и лёгкий вариант под Telegram WebView |
| Backend | FastAPI + Pydantic v2 | быстрый, типизированный, авто-доки на `/docs` |
| БД | SQLite через SQLAlchemy | 0 ₽, ноль настройки, один файл; замена на Postgres = одна строка `DATABASE_URL` |
| Vision | Pillow | офлайн, без моделей и ключей; опциональный апгрейд до GPT-4o-mini / Gemini |
| Тесты | pytest + vitest/RTL | покрывают и движок, и HTTP, и UI |
| Хостинг | один процесс, один порт | Mini App требует HTTPS-статики — её отдаёт тот же FastAPI |

## Как считает Fashion Ranking Engine

Каждый товар получает оценку 0…1 как взвешенную сумму восьми факторов:

| Фактор | Вес | Что измеряет |
| --- | --- | --- |
| `style` | 0.28 | попадание в выбранный стиль (точное / соседнее / чужое) |
| `silhouette` | 0.16 | совместимость кроя с силуэтом (рост + вес + фото) |
| `mood` | 0.15 | совпадение с настроением |
| `color` | 0.15 | гармония цвета с палитрой пользователя и его любимыми цветами |
| `formality` | 0.08 | соответствие поводу (работа, свидание, событие…) |
| `value` | 0.08 | рейтинг, число отзывов, честность цены к медиане категории |
| `season` | 0.05 | сезонность, включая соседние сезоны |
| `verification` | 0.05 | насколько товар проверен |

Веса настраиваются через `RANKING_WEIGHTS_JSON` без изменения кода и всегда нормализуются к 1.

Дальше:

1. **Жёсткие фильтры** — товар не рассматривается, если он дороже бюджета, не прошёл
   верификацию, состоит только из нелюбимых цветов, не имеет нужного размера или не подходит
   по посадке. Причины попадают в `diagnostics.rejected_sample`.
2. **План образа** — многослойный, лёгкий или «на основе платья» (зависит от сезона, повода и
   бюджета: при бюджете < 15 000 ₽ верхняя одежда убирается первой).
3. **Бюджетный оптимизатор** — сначала распределяет бюджет по слотам, затем «ремонтирует» образ
   вниз (самые дешёвые потери качества на рубль), затем докупает апгрейды с лучшей отдачей на
   рубль. Необязательные слоты (сумка, аксессуар) могут быть убраны. Алгоритм детерминированный:
   одинаковый вход → одинаковый образ.
4. **Цельность образа** — отдельно считается согласованность цвета, стиля и формальности; итоговые
   0…100 = 62 % средняя оценка вещей + 38 % цельность. Отсюда же вердикт A/B/C/D.
5. **Объяснения** — для каждой вещи генерируются причины на русском, а не «AI так решил».

## Product verification layer

Каждая карточка товара проходит 9 проверок; критическая ошибка означает, что товар **не попадёт
в образ вообще**:

| Проверка | Вес | Критическая |
| --- | --- | --- |
| `schema` — обязательные поля | 0.18 | да |
| `price` — вменяемая цена в ₽ (≤ 100 000) | 0.15 | да |
| `url` — https + хост из белого списка (защита от SSRF) | 0.20 | да |
| `category` — категория известна движку | 0.10 | да |
| `source` — доверенный источник | 0.08 | да |
| `checksum` — карточка не изменена после верификации | 0.04 | да |
| `attributes` — цвета/стили/сезоны заполнены | 0.12 | нет |
| `sizes` — указаны размеры | 0.10 | нет |
| `freshness` — TTL верификации (30 дней) | 0.03 | нет |
| `reachability` — живой HTTP-запрос | 0.05 | нет, по умолчанию **выключено** |

Статусы: `verified` (≥ 0.92 и без критических ошибок), `warning` (≥ 0.6), `failed`.
Отчёт доступен в приложении («Проверка товаров») и в `GET /api/catalog/verification`.

В демо-каталоге намеренно лежат 4 битые карточки (`BAD-001…BAD-004`): ссылка на чужой хост,
нулевая цена, отсутствие атрибутов, неизвестная категория. Все четыре отклоняются.

## API

Полная документация — `http://localhost:8000/docs`. Основное:

| Метод | Путь | Назначение |
| --- | --- | --- |
| `GET` | `/api/health` | состояние, режим, счётчики БД |
| `GET` | `/api/meta` | стили, настроения, поводы, цвета, лимиты бюджета, веса |
| `POST` | `/api/telegram/auth` | авторизация по `initData` или демо-идентичность |
| `POST` | `/api/looks/generate` | собрать образ (`multipart/form-data` с фото **или** JSON) |
| `GET` | `/api/looks` | история образов пользователя |
| `GET` | `/api/looks/{id}` | образ целиком |
| `POST` | `/api/looks/{id}/swap` | заменить вещь в слоте, не трогая остальные |
| `POST` | `/api/looks/{id}/favorite` | избранное |
| `GET` | `/api/catalog/items` | каталог с фильтрами |
| `GET` | `/api/catalog/verification` | отчёт верификации |
| `POST` | `/api/catalog/import` | импорт внешних товаров (каждый проходит верификацию) |
| `POST` | `/api/catalog/reverify` | повторная верификация каталога |

Пример:

```bash
curl -s -X POST localhost:8000/api/looks/generate \
  -F style=old_money -F mood=elegant -F season=autumn \
  -F height_cm=182 -F weight_kg=78 -F budget_rub=75000 \
  -F preferred_colors=camel,navy -F photo=@me.jpg | jq '.items[] | {slot, name, price_rub, score}'
```

## Режимы работы

**Демо / локальный** (`DEMO_MODE=true`, по умолчанию) — не нужен ни токен бота, ни сеть, ни
ключи AI. Фото анализируется Pillow, каталог сидируется из репозитория, пользователи создаются
как локальные демо-идентичности. Идеально для разработки и ревью.

**Telegram** — задайте `TELEGRAM_BOT_TOKEN`, соберите фронтенд, выложите его на HTTPS и укажите
`TELEGRAM_WEB_APP_URL`. Подпись `initData` проверяется по стандартному алгоритму HMAC-SHA256
(`backend/app/telegram/auth.py`), просроченные и подделанные данные отклоняются.

**AI-провайдер** — `AI_PROVIDER=local|openai|gemini`. Если удалённый вызов не удался, приложение
молча возвращается к локальному анализу: образ соберётся в любом случае.

## Приватность

Фото по умолчанию **не сохраняется**: из него извлекаются признаки (доминирующие оттенки,
подтон, пропорции), а байты отбрасываются. В образе остаётся только SHA-256-отпечаток — чтобы
повторная генерация была воспроизводимой. `STORE_PHOTOS=true` включает сохранение, если оно
вам действительно нужно.
